## What changed

- **`9-bookmark-types.ts`**: links have `iconId` instead of an inline `icon`. The document carries `icons: Record<IconId, string>`.
- **`io/icon-id.ts`** (new): the cache key is a hash of the icon's data URL, so identical icons get the same id automatically, including across imports.
- **`netscape-parse.ts`**: the parser moves each `ICON` into the cache.
- **`netscape-serialize.ts`**: export writes `ICON=` back from the cache, so exported files keep the same format.
- **`3-local-storage-items.ts`**: the tree is stored under `tm-tmarks-tree-v2`, and the icons under `tm-tmarks-icons-v1`. Icons are rewritten only when the cache changes, so routine edits no longer re-serialize every icon. Existing `tm-tmarks-tree-v1` data is migrated on first load. The old key is removed only after the new data is saved.
- **`a-bookmarks-atoms.ts`**: adds `bookmarkIconsAtom` and `itemIconAtom(id)`.
- **`a-bookmarks-actions.ts`**: load, import, append, export, and clear carry the cache. Delete drops icons that no link uses anymore.
- **`7-item-preview.tsx`**: reads its icon from `itemIconAtom`.

## Issues to consider

1. **There is still a size ceiling.** localStorage is a few MB per origin in total. Deduplication helps a lot when icons repeat, but a library with many distinct favicons can still hit the quota. If your measurements show you are still close to the limit, the next step is moving icons to IndexedDB. The id-keyed cache maps directly onto an IndexedDB store, so this design doesn't block that.
2. **Hash choice.** I used cyrb53, a 53-bit non-cryptographic hash. A collision would show the wrong favicon but would not lose bookmarks. SHA-256 needs `crypto.subtle`, which is unavailable on plain-HTTP origins, so I avoided it.
3. **Two keys are not atomic.** Icons are written before the tree. If the tree write fails after a delete pruned an icon, the stored tree can point at a missing icon. That item shows the default globe, and nothing crashes. The orphaned data is cleaned up on the next delete.
4. **Garbage collection runs only on delete.** Append-import keeps existing icons on purpose, since they are still referenced.
