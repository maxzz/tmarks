Drag-and-drop is implemented for both panels, and the tree folders collapse and expand as you described. I tested it in the browser (with simulated pointer events, not a real mouse) and the typecheck and unit tests pass.

**What works**
- **Right panel → right panel:** dragging a link or folder to a new position. Drop on the top or bottom edge of a row to place it before or after; in grid view, the left or right side.
- **Into a folder:** dropping on the middle of a folder row (in either panel) moves the item inside it.
- **Left panel:** the same rules apply to tree rows. Dragging a right-panel item onto a tree folder moves it in. Tree folders can also be dragged.
- **Auto-expand:** hovering a collapsed tree folder that has sub-folders for about 500ms opens it, so you can drop into its children.
- **Multi-select:** dragging a selected item drags the whole selection in that panel, keeping on-screen order.
- **Cannot drop a folder into itself or its own sub-folder**; the indicator disappears instead.
- **Escape** cancels a drag. Dragging near the top or bottom of a panel auto-scrolls it.

**Implementation**
- The new code is in `src/components/2-main/4-dnd/`, split into types, pure rules, Jotai atoms, the move action, the controller, the Motion UI, and a test file.
- It uses pointer events rather than native HTML5 drag-and-drop. Native drag would have triggered the existing file-drop handler and shown an "Unsupported file" toast on every internal move.
- Motion drives the drag preview, the spring-animated drop indicator, and auto-scroll.
- State lives in Jotai atoms. I added no `useCallback` or `useEffect` to components.
- Small edits to existing files: `tree-panel.tsx` and `items-panel.tsx` gained drag attributes and a pointer-down handler. `0-main-all.tsx` mounts the layer. `7-item-preview.tsx` now sets `draggable={false}` on icons, so the browser doesn't start a native image drag.

**Decisions I made that you may want to change**
1. Dropping before or after a folder row in the tree is allowed (it reorders folders and moves items into the parent).
2. Dropping into a folder also opens that folder, so the moved item is visible.
3. A folder expanded by hover stays open even if the drag is cancelled.
4. Moves have no undo. Dragging an item back is the only way to reverse one.
5. A drop before or after an item that is itself part of the dragged selection does nothing.
