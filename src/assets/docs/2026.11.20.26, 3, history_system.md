**How it works**
- **State:** I used Jotai, not Valtio. The bookmark document is already Jotai atoms holding immutable values, so undo and redo are two stacks of snapshots. `canUndo` and `canRedo` are derived atoms. Valtio would have deep-proxied every bookmark in every snapshot.
- **Tracking:** A store subscription watches the three document atoms, and the changes from one action become one step. No existing action had to opt in, so future operations are covered.
- **Scope:** Items, folders, and icons are tracked. Selection and expansion are not, so undo doesn't move the view. After an undo, selected ids that no longer exist are cleared.
- **Components:** No `useCallback` or `useEffect` in the new code. Buttons use `useAtomValue` and `useSetAtom`.
