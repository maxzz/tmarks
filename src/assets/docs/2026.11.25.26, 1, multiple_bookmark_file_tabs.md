**What's new for the user**
- **Tab strip** above the panels, with a "+" button and a close button on each tab; middle-click also closes. The menu gained **New tab** and **Close tab**.
- **Import or drop opens each file in its own tab.** An empty, unchanged tab gets reused, so no stray "Untitled" tab is left behind. The old Replace / Add-as-folder dialog is gone.
- **Clipboard across tabs.** Copy in one tab and paste in another. Cut and paste moves the items, so they leave the source tab. Each tab gets its own undo step, and moved items keep their dates.
- **Dragging onto a tab header** drops the items into the folder that tab is showing. Resting on a header for about 0.6 s opens that tab, so you can drop at an exact spot. Holding Ctrl (Cmd on macOS) when you release copies instead of moving.
- **System clipboard.** Copy and Cut also write an HTML list of links and a plain list of URLs, for pasting into other apps.
- **Unsaved-changes marker.** A dot on the tab means it has changed since it was opened or saved. Undoing back to the saved state clears it. Closing a marked tab asks Save / Don't save / Cancel. Save downloads under the tab's original file name.
- **Each tab keeps its own** undo/redo history, selection, open folders and pinned folder.
- **Persistence.** All tabs, the shown tab and the modified markers survive a reload. The trees are now stored in IndexedDB, and the existing single localStorage tree is moved into the first tab once and then removed.

**How it's built**
- `src/store/tabs/` holds the store side: pure rules with tests (`0-tabs-logic.ts`), Jotai atoms, the swap, the actions and IndexedDB storage.
- The existing atoms still always mean "the shown tab". Switching tabs parks that state in `tabSessionsAtom` and loads the other tab's, so the tree, items, DnD, dialogs and history code barely changed.
- `src/components/2-main/6-tabs/` holds the tab strip, the area wrapper and the close dialog. Components only read atoms and call write atoms: no `useEffect`, `useCallback` or `useState`.
- The system clipboard writer is in `src/store/io/system-clipboard.ts`.

**Changes to existing code**
- The history module now exports `takeHistoryAtom` and `putHistoryAtom`, so tabs can give up and take back their undo stacks.
- `a-bookmarks-atoms.ts` lost its localStorage startup and saving; the tabs module does that now.
- The clipboard records which tab the items came from.
- The DnD session and drop target carry tab ids, and the drag preview shows a stored label.
- `saveBookmarksAtom` and the import dialog code were removed.

**Limits**
- Pasting inside the app does not read the system clipboard, so items can't move between two browser windows of the app.
- Two browser windows of the app write to the same IndexedDB and overwrite each other, as they did with localStorage before.
- Tabs can't be renamed or reordered yet.
- Pasting from a tab that has since been closed shows a message instead of pasting.
